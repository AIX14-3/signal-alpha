# 지정학 리스크 차단(Kill-Switch) 요약 — 단독 라인

> 전쟁·분쟁 등 지정학 리스크 구간에서 잘못된 투자 신호가 나가지 않도록,
> 홈페이지/리포트를 **일시 차단**하는 안전장치. 상세본: `docs/geo-risk-block-detail.md`
>
> ⚠️ **단독(Standalone) 베이스라인**: 기존 테이블·기존 코드 재사용 안 함. 전용 테이블(`guard_*`)·
> 전용 API(`/api/guard/*`)·전용 패키지(`app/homepage_guard/`)로 독립. 기존 워커 프로세스 위에서 실행만 공유.

## 왜?
리포트 신호는 지정학 충격을 반영하지 못함 → 전쟁/휴전 속보 때 신호와 실제 주가가 어긋남.
**확신이 없으면 잠시 멈추고 안내(fail-safe)** 하는 게 안전.

## 어떻게? (핵심 1줄)
전용 테이블 **`guard_site_status` 값 1행**을 두고, 통제 라인(전용 API)·프론트가 그 값을 읽음.
→ **값 하나만 바꾸면 즉시 반응**(재시작 불필요, 단일 진실원천). 기존 코드/테이블과 분리.

```
[관리자 수동 / 에이전트 자동] → guard_site_status(전용 DB) → [전용 공개 API → 프론트 화면]
```

## 차단 범위(scope) 3단계 — 약→강 (전부 serving/프론트 edge에서 enforce)
| 단계 | 막는 것 | 그대로인 것 |
|------|---------|-------------|
| `report_generation` | 새 신호 **노출**(배너 안내) | 홈·검색·기존 리포트 조회 |
| `report_view` | 리포트 **조회**까지 | 홈·검색 |
| `whole_site` | **전 페이지** | `/login` `/signup` `/pricing` `/admin`만 예외 |

> 리포트 "생성" 자체를 끊는 건 기존 파이프라인 수정이 필요 → 단독 원칙상 기본은 **노출 차단**으로 처리.
> 생성까지 끊으려면 `guard_site_status`를 읽기 전용 참조하는 **최소 훅(선택적, 기본 비활성)**.

## 발동 방식(mode)
- `manual` — 관리자가 직접 ON/OFF (가장 안전)
- `advisory` — 에이전트가 **제안**, 관리자가 승인 ★권장 기본값
- `auto` — 에이전트가 **자동** 차단/해제 (빠름, 안전장치 필수)

## 전파 경로 2 (모두 단독 라인, 기존 코드 미수정)
1. 전용 공개 API `GET /api/guard/status` (프론트가 폴링)
2. 프론트 전용 통제 게이트가 scope에 맞춰 배너/부분차단/전체차단 렌더 (이미 만든 위험 신호의 "노출"을 막음)

## 전용 구성 (독립 패키지/테이블/API)
- 패키지 `app/homepage_guard/` — 자체 LLM 클라이언트·수집기·판정·게이트 (DART LLM 미공유, 외부 import 없음)
- 테이블 `guard_site_status` / `guard_news_events` / `guard_recommendations` / `guard_status_audit`
- API `/api/guard/*` (전용 라우터), 데몬은 워커 프로세스 lifespan에서 실행만 공유

## 안전장치 (핵심만)
- `auto`는 scope 상한(예: 자동은 `report_generation`까지) + 쿨다운
- `/admin`·`/login`은 항상 예외 (관리자 잠김 방지)
- 모든 변경은 감사 로그(`guard_status_audit`) 기록 / `resume_at` 으로 방치 방지
- 전용 API 장애 시 화면은 **fail-open**(정상 노출)으로 두어 장애 확산 방지

## 사용자 화면
- 전체/조회 차단: "서비스 일시 중단 안내" + 사유 + [요금제/로그인]
- 생성(노출) 차단: 상단 배너 "신규 분석 일시 중단 — 기존 리포트는 참고용"

## 데이터
기존 신호·리포트 데이터는 **건드리지 않음**. 통제 라인은 "노출"만 일시 중지 → 해제 시 즉시 원복.
