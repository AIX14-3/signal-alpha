# DataLab 이벤트 리드-래그 스터디 (Stage 6) — "사건 키워드"로 검증

**날짜**: 2026-06-25
**worktree/브랜치**: `sa-ml-longhorizon` / `feat/ml-datalab-longhorizon`
**선행**: 6/23 DataLab 단독 무신호, 6/24 long-horizon 피벗, 6/25 Stage5(시대별 특허 키워드도 무신호)

## 질문

앞선 실험들은 "키워드를 잘못 골라서 무신호인가?"를 의심하게 했다. 그래서 **결과(주가가 크게 움직임)를
알고**, 그 변동을 일으킨 **실제 사건의 키워드**를 가져와 DataLab 검색량이 주가와 어떤 시간 관계인지 본다.

후견 편향 때문에 이건 **예측 백테스트가 아니라 리드-래그 검증**이다. 두 가지를 가른다:
- **데이터 소스가 시장을 움직인 사건을 *포착*하는가?** (검증)
- **검색이 가격보다 *먼저/동시/나중*에 움직이는가?** (리드-래그)

## 셋업

1. **사건 탐지(객관, 가격만)**: `detect_price_events.py` — 3종목(삼성·하이닉스·네이버) 2016~2026
   주간 |초과수익|(벤치 KS11) 상위 8개씩, 3주 갭 dedup = **24개 큰변동 주차**.
2. **사건 식별·키워드 부여(웹/LLM)**: 종목별 리서치 에이전트가 각 주차의 실제 사건을 웹검색으로 규명하고
   네이버 검색가능 키워드 부여. 예: 삼성 2016-08 갤럭시노트7, 2018-01 반도체 고점론, 네이버 2022-10
   포시마크 인수, 하이닉스 2024-09 마이크론 실적, 2026-06 엔비디아 등.
3. **DataLab 신규 수집**: `collect_datalab_for_keywords.py`로 42 키워드(주+대체) 전체기간 주간 1회 →
   **39개 데이터 확보**(prod 쓰기 0). 사건당 키워드 시리즈 매핑(데이터 없으면 대체 키워드 폴백).
4. **분석**: `event_study_leadlag.py` — (A) 사건 주변 [-8..+8]주 z-score 검색 프로파일 평균,
   (B) 전구간 검색모멘텀↔초과수익 교차상관(lag).

## 결과

### (A) 사건 중심 검색 프로파일 (z-score, 22/24 사건)

| offset(주) | … | −2 | −1 | **0(변동주)** | +1 | +2 | … |
|---|---|---|---|---|---|---|---|
| mean z | | +0.28 | +0.44 | **+1.04** | −0.13 | −0.30 | |

→ **검색은 가격 변동 주(offset 0)에 뚜렷이 피크**(z≈+1.0)하고, 직전 1~2주에 완만히 차오른다(−1=+0.44,
−2=+0.28). 즉 **동시(coincident)** — 변동 주에 가장 강하다.

**정렬 주의(중요·수정 반영)**: Naver 주간 데이터는 **월요일**, 가격 주차는 **금요일**(주 마지막 거래일)에
찍힌다. 처음엔 날짜+허용오차로 맞췄는데, offset 0(금) 기준 *다음 주 월요일*이 3일·*같은 주 월요일*이 4일이라
nearest가 다음 주로 스냅 → 전체 축이 +1 밀려 "−1 선행"처럼 보였다. **ISO 주 인덱스로 정렬**해 offset 0=변동
주로 고정하니 피크는 **−1이 아니라 0(동시)**. (코드리뷰에서 발견·수정.)

### (B) 전구간 교차상관 (검색모멘텀 vs 초과수익, 23쌍)

모든 lag에서 |corr| ≤ 0.05 (최대 +0.049 @ lag +1). **사실상 0.**

## 해석 (핵심)

**DataLab은 시장을 움직인 사건을 "본다" — 검색은 큰 변동과 *같은 주*에 피크(z≈+1.0, 동시).
그러나 무조건부 예측력은 0이다.** 이 둘은 모순이 아니다:

- (A)는 **후견으로 사건·키워드를 골라** 조건부로 본 것 → "어떤 사건·키워드인지 알면" 검색이 변동 주에
  강하게 동반(직전 1~2주 완만한 상승은 있으나 피크는 동시). 즉 데이터 소스는 현실을 반영한다(검증 성공).
- (B)는 **사전에 알 수 없는** 전구간 테스트 → 검색 급등 대부분은 주가와 무관, 모든 lag에서 상관 ≈0
  (동시 lag 0 포함 +0.045). **사전에 어느 키워드의 스파이크가 주가로 이어질지 모르기 때문에 단독 거래 불가.**

추가로 사건 다수가 실적·예정 이벤트(어닝, 합병설, 방한 기대)라 관심(검색)이 변동 주에 동반되지만, 이는
**방향**을 알려주지 않는다 — (B)가 동시 lag에서조차 부호 상관 ≈0으로 이를 확증.

## 결론

- 6/23·6/25의 "무신호"는 **데이터 소스가 눈멀어서가 아니다** — DataLab은 시장 사건을 **동시에 포착**한다
  (반응형/확인형). **하지만 (i) 검색이 가격보다 앞서지 않고(동시), (ii) 키워드를 사전에 고를 수 없으며,
  (iii) 동시 상관조차 ≈0이라 단독 예측 신호는 0**(앞선 결론과 일관).
- 함의: DataLab은 **단독 수익률 예측기**가 아니라 제품 설계대로 **근거·흔적 확인**(사건이 실재하고 관심이
  쏠리는지)과 **다중소스 융합의 확인 피처**로 써야 한다(docs/project-context.md §9/§10, backtesting-plan §6).
  동시성(나우캐스팅)·이벤트 탐지에는 쓸모가 있으나 **선행 예측엔 부적합**.

```bash
cd services/agent-worker

  --benchmark KS11 --tickers 005930,000660,035420 --top-n 8 --out price_events.json

  --keyword-csv event_datalab.csv --prices-csv prices_kospi15_2016_2026.csv --benchmark KS11 --k 8
```
