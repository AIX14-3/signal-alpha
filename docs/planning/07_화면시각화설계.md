# 07. 화면·시각화 설계 — 상세 스펙 `[계획]`

> Signal α 하위 문서 | 상위: [00_메인_기획서.md](00_메인_기획서.md)

> **구현 현황**: `web/`은 Next.js 골격(레이아웃 + 단일 페이지)만 존재한다. 대시보드·드릴다운·백테스팅 탭과 분석 트리거/SSE API는 전부 미구현이다. main-server에는 현재 health·signals 조회 라우트만 있다.

---

## 7.1 레이어 구조 (3단계 드릴다운)

| 단계 | 위치 | 차트 유형 | 목적 |
| --- | --- | --- | --- |
| 1단계 요약 | 메인 대시보드 | 레이더 차트 | 소스 균형 한눈에 파악 |
| 2단계 소스별 | 분석 카드 | 점수 게이지 바 | 소스별 점수 비교 |
| 3단계 근거 | 드릴다운 | 소스별 상세 차트 + 원문 링크 | 근거 투명성 확보 |

---

## 7.2 드릴다운별 차트 선택 근거

| 소스 | 차트 유형 | 선택 이유 |
| --- | --- | --- |
| 공시 (DART) | 타임라인 | 공시는 시간순 맥락이 중요. 연속성 파악 가능 |
| 리포트 | 막대 + 추이선 | 증권사별 분포 + 3개월 목표가 추이 동시 확인 |
| 대안 (채용) | 수평 막대 | 직군별 변화율 비교 |
| 대안 (특허) | 버블 차트 | 기술 카테고리 × 출원 수 × 신규 여부 동시 표현 |
| 대안 (검색) | 라인 차트 | 검색량 트렌드 (최근 4주) |
| 토론 | 텍스트 카드 + 게이지 | 논거는 텍스트, 세기는 게이지로 분리 |
| 주가 | 추세·수급 지표 차트 | 이동평균·RSI·수급 흐름 |

## 7.3 메인 대시보드 구성

### 좌측 — 메인 스코어 카드

- 종목명 + 분석 시각
- 종합 점수 (0~100) — 큰 숫자로 강조
- 방향 배지: POSITIVE / NEGATIVE / MIXED
- 소스 일치도: HIGH / MED / LOW
- 한 줄 요약 (Judge AI 출력)
- 60점 미만 시: 추가 확인 필요 경고 배너

### 우측 — 소스별 결과 카드

각 소스 카드: 점수 + 방향 + 핵심 지표 + 원문 링크. 클릭 시 드릴다운으로 이동.

### 하단 — 토론 요약

- Bull 논거 / Bear 논거 / Judge 최종 판단

## 7.5 백테스팅 결과 탭 (별도)

서비스 대시보드와 분리된 별도 탭. 모델 검증 결과를 시각화한다.

| 차트 | 내용 |
| --- | --- |
| 점수 구간별 적중률 히트맵 | 40점 이하 / 40~70 / 70점 이상 × 소스별 |
| 방식별 정확도 비교 | D-1 ~ D-5 정확도 + 비용/건 바 차트 |
| 대안 데이터 선행성 검증 | 채용 급증 → 공시 발생 → 주가 반응 평균 일수 타임라인 |

---

## 7.6 데이터 흐름 (FE ↔ BE)

```
1. 사용자 종목 입력
        ↓
2. POST /api/analyze { stock_code }
        ↓
3. SSE 스트림 구독: GET /api/analyze/{code}/stream
        ↓
4. 이벤트 수신 순서:
   - dart_complete (점수, 공시)
   - report_complete (점수, 의견)
   - alt_complete (점수, 채용·특허·검색)
   - price_complete (점수, 지표)
   - debate_complete (최종 점수, 토론)
        ↓
5. 최종 결과 렌더링
```

처리 방식은 SSE 기반 "분석 중..." → 완료 순차 노출. 사용자는 에이전트가 순서대로 완료되는 과정을 실시간으로 본다.

> 위 API는 설계안이다. 현재 main-server에는 `/health`·시그널 조회 라우트만 구현되어 있고, 분석 트리거·SSE 엔드포인트는 미구현이다. 구현 시 [`docs/api.md`](../api.md)와 정합을 맞춘다.
