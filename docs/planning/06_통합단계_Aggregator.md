# 06. 통합 단계 (Aggregator) — 상세 스펙 `[계획]`

> Signal α 하위 문서 | 상위: [00_메인_기획서.md](00_메인_기획서.md)

통합 단계는 두 개의 통합기로 구성된다. 대안 데이터를 묶는 `Alt_Aggregator`와, 전체 소스를 종합 판단하는 `Debate_Aggregator`다.

> **구현 현황**: D-1 룰베이스 통합은 `AGGREGATE_SIGNAL` 큐 작업으로 구현되어 `agent_results`를 읽고 `final_signals`를 생성한다. Report valuation summary와 내부 `scenario_band`는 최종 `score_breakdown.REPORT.valuation`과 caution evidence에 전달된다. D-2~D-5 토론/투표 방식은 계획 상태다.

---

## 6.1 Alt_Aggregator (대안 데이터 통합)

채용·특허·검색 3개 분석 신호를 묶어 단일 alt 신호를 산출한다. 순수 통합 로직만 담당하며 개별 분석은 하지 않는다.

| 항목 | 내용 |
| --- | --- |
| 입력 | hiring · patent · datalab 분석 신호 |
| 출력 | score, signal, hiring_summary, patent_summary, datalab_summary, cross_signal |
| 핵심 가치 | 채용·특허·검색이 동시에 같은 방향을 가리킬 때 신뢰도 상승 (cross_signal) |
| 사용 모델 | Gemini 3 Flash (통합 요약) |
| 담당 | 이슬 |

> 책임 분리 원칙: Analyzer는 "연결자(개별 분석 실행)", Aggregator는 "통합기(합치는 자)". 하나의 모듈이 분석과 통합을 모두 담당하지 않는다.

---

## 6.2 Debate_Aggregator (종합 판단)

전체 분석 신호를 받아 최종 점수를 산출한다. 팀원 5명이 각기 다른 방식으로 종합 로직을 구현하고 백테스팅으로 정확도를 비교한 뒤, 5개 방식을 앙상블한다.

### 구현 방식 5가지 (1인 1방식)

| 방식 | 설명 | 담당 |
| --- | --- | --- |
| D-1 룰베이스 | 가중 평균 + 조건 보정. 비교 기준점(Baseline) | 성진 |
| D-2 단일 AI 판단 | 분석 신호를 하나의 LLM에 투입해 판단 | 규태 |
| D-3 멀티 페르소나 토론 | 긍정 AI → 주의 AI → 심판 AI 순차 토론 | 광현 |
| D-4 선행성 가중 | 선행성 강한 소스일수록 높은 가중치 부여 후 합산 | 은진 |
| D-5 멀티 AI 투표 | 서로 다른 제공사 모델의 독립 판단 → 다수결/가중 투표 | 이슬 |

---

## 6.3 D-4 선행성 가중 — 가중치 설계

선행성이 강한 데이터일수록 높은 가중치를 부여한다. "변화는 채용·특허처럼 선행 지표에서 먼저 나타나며, 주가·리포트는 이를 뒤늦게 반영한다"는 가설을 직접 구현한 방식이다.

| 소스 | 선행성 | 가중치(초안) |
| --- | --- | --- |
| 채용 | 가장 선행 | 0.30 |
| 특허 | 선행 | 0.25 |
| 검색 트렌드 | 선행 | 0.20 |
| 공시 | 반응 | 0.15 |
| 리포트 | 후행 | 0.10 |
| 주가(Price) | 검증용 | 0.00 (가중 제외) |

> 가중치는 초안이며 백테스팅 결과로 조정한다. 다른 4개 방식과 적중률을 비교해 최종 앙상블 비율을 결정한다.

---

## 6.4 토론 구조 (Debate)

| 역할 | 정의 |
| --- | --- |
| 긍정 AI (Bull) | 긍정 방향 사실만 정리. 주가·매매 판단 제외 |
| 주의 AI (Bear) | 리포트 충돌, 트렌드 약화, 표본 부족 등 주의 사실 정리 |
| 심판 AI (Judge) | 양측 근거 종합 → 방향 일치 여부와 최종 점수 결정 |

---

## 6.5 분석 실패 시 처리 정책

| 실패 수 | 처리 | 점수 상한 |
| --- | --- | --- |
| 0개 | 전체 분석 제공 | 제한 없음 |
| 1개 | 분석 제공 + CAUTION 배너 | 제한 없음 |
| 2개 | 분석 제공 + WARNING 배너 | 40점 상한 |
| 3개 전부 | 분석 미제공 + 재시도 버튼 | — |

대시보드 경고 배너 예시:

```
⚠ 대안 신호 데이터 수집 실패
   해당 분석기는 중립값으로 대체됨
   실제 점수보다 낮을 수 있음
```

> 경고 단계는 `final_signals.warning_level`(NORMAL / CAUTION / WARNING)로 스키마에 반영되어 있다.

---

## 6.6 최종 출력 필드

`score` · `consensus_score` · `signal` · `source_agreement` · `bull_argument` · `bear_argument` · `summary` · `needs_review`

> **용어 원칙**: 사용자 노출 문구·발표자료에서 `confidence`라는 단어는 피한다 — 투자 조언의 신뢰도처럼 해석될 수 있다. `consensus_score` / `alignment_rate` / `source_agreement`를 사용한다 (`docs/project-context.md` 원칙).
> 단, DB 내부 컬럼명으로는 `final_signals.confidence`가 존재한다(팀 ERD 병합 결과). 내부 컬럼과 노출 용어를 구분해 사용한다.

### 출력 예시

```
종합 점수: 87점
방향: 긍정 (POSITIVE)
소스 일치도: HIGH (3개 소스 모두 같은 방향)

Bull 논거: 채용 +240%, 특허 신규 카테고리, 공시 3건 긍정 방향 일치
Bear 논거: 리포트 목표가 격차 크고 DataLab 검색량 상승 아직 미약

한 줄 요약: 공시 3건 긍정, 리포트 목표가 112,000원(괴리율 31.8%).
            채용·특허 모두 확장 방향. 리포트 의견 일부 충돌 주의.
추가 확인 필요: 아니오
```
