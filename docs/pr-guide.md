## ⚡ 빠른 시작 — PR 올리는 3단계

```bash
# 1. 브랜치 만들기  (종류/이슈번호-짧은설명)
git switch -c feat/issue-12-dart-collector

# 2. 작업 후 커밋 (한 PR엔 한 가지 일만!)
git add . && git commit -m "feat: DART 공시 수집기 추가"

# 3. 푸시하고 PR 열기 → 템플릿이 자동으로 뜹니다
git push -u origin feat/issue-12-dart-collector
```

PR 창이 뜨면 템플릿 칸을 채우고, 아래 **체크리스트만** 확인하면 끝입니다.

| ✅ 올리기 전 마지막 점검 | |
|---|---|
| **작게 쪼갰나?** | 한 PR = 한 가지 일 |
| **무엇을·왜 적었나?** | 템플릿 `설명` + `변경 내용` |
| **추천처럼 들리는 말 없나?** | [규칙 1](#규칙-1--투자-추천처럼-들리는-말-금지-가장-중요) — 가장 중요 |
| **돌려봤나?** | 로컬에서 실행/테스트 |
| **이슈 연결했나?** | `Closes #번호` |

## 🤔 왜 이런 규칙이 있나요?

Signal α는 **매수·매도를 추천하는 서비스가 아닙니다.**
여러 데이터 출처(DART 공시·리포트·대체데이터)가 **같은 방향을 가리키는지 교차검증해서 보여주는 서비스**입니다.

> 법적으로 "이 종목 사세요" 같은 **투자 권유**는 자격증(투자자문업 등록)이 있어야 할 수 있습니다.
> 그래서 우리 규칙의 핵심은 **"추천처럼 들리지 않게, 사실과 방향만 전달하기"** 입니다.

---

## 🔒 필수 규칙 5가지

### 규칙 1 · 투자 "추천"처럼 들리는 말 금지 (가장 중요)

- **무엇을**: 화면 글자·API 응답·AI 프롬프트 어디에도 "사세요 / 파세요 / 추천 / 오를 겁니다 / 달성 확실" 같은 **권유 표현**을 쓰지 않습니다.
- **어떻게**: 금지할 표현은 코드 여기저기 흩지 말고 **한 파일에 목록으로 모아 두고**(상수화) 코드가 자동으로 걸러냅니다.
- **대신**: "출처 3곳 중 2곳이 긍정적입니다" 처럼 **사실·방향만** 전달합니다.

> 💡 원래 규칙: `INVESTMENT_RECOMMENDATION_PHRASES: 투자자문업 규제 대상 표현 30개 상수화`
> 👉 **쉽게**: 투자 권유로 들리는 금지어 약 30개를 한 목록 파일에 모아두고, 코드가 자동으로 막는다.

### 규칙 2 · `confidence`(확신도) 단어 쓰지 않기

- `confidence` 대신 `consensus_score`(의견 일치 점수) · `alignment_rate`(방향 일치율) · `source_agreement`(출처 동의)를 씁니다.
- **왜?** "확신도 90%"는 "오른다고 확신"처럼 들립니다. 우리는 "데이터들이 얼마나 같은 방향인가"만 말합니다.

### 규칙 3 · 역할 섞지 않기 (수집 / 분석 / 조율)

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **Collector**(수집기) | 외부 데이터만 가져오기 | 방향·점수·요약 만들기 ❌ |
| **Analyzer**(분석기) | 저장된 데이터만 해석 | 외부 API 직접 호출 ❌ |
| **Orchestrator**(조율) | 순서만 관리 (수집→분석→통합) | 데이터 가공 ❌ |

### 규칙 4 · 저장 위치 섞지 않기

| 결과 | 저장 위치 |
|---|---|
| 수집 결과 | `raw_evidence` 에만 |
| 분석 결과 | `source_results` 에만 |
| 통합 결과 | `signal_snapshots` 에만 |

> 원본과 해석을 섞으면 나중에 검증·복기가 불가능합니다.

### 규칙 5 · 외부 API가 실패해도 화면이 죽지 않게

- 외부 호출이 실패하면 **미리 만든 대체 데이터**(fixture/mock)로 화면을 유지하고 `needs_review: true`(검토 필요)를 남깁니다.
- **왜?** 발표·데모 중 외부 API 하나 막혔다고 전체가 멈추면 안 됩니다.

## 📚 어려운 용어 → 쉬운 말 사전

| 어려운 말 | 쉬운 말 |
|---|---|
| 투자자문업 규제 대상 표현 | 자격 없이 쓰면 안 되는 "투자 권유" 말들 |
| 상수화 (常數化) | 여기저기 흩지 말고 **한 파일에 목록으로 모아 두기** |
| 금지 표현 필터 | 목록에 있는 말이 결과에 들어가면 **자동으로 막는 코드** |
| `consensus_score` | 출처들이 **얼마나 같은 의견인지** 점수 (확신도 아님) |
| `alignment_rate` | 출처들의 **방향이 얼마나 일치하는지** 비율 |
| `raw_evidence` | 가공하지 않은 **원본 근거 데이터** |
| `source_results` | 출처별로 **해석한 결과** |
| fixture / mock | 외부 API 대신 쓰는 **미리 만든 가짜 데이터** |
| `needs_review` | "이 결과는 **사람이 한 번 더 봐야 함**" 표시 |

## 🏷️ 이름 짓기 규칙

**브랜치** — `종류/이슈번호-짧은설명`
`feat/issue-12-dart-collector` · `fix/issue-20-filter-bug` · `docs/issue-7-pr-guide`

**PR 제목** — `[종류] 무엇을 했는지 한 줄`
`[feat] DART 공시 수집기 추가` · `[docs] PR 작성 가이드 추가`

| 종류 | 언제 쓰나 |
|---|---|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작은 그대로, 코드만 정리 |
| `docs` | 문서만 변경 |
| `chore` | 설정·빌드·CI 등 자잘한 작업 |
| `perf` | 성능 개선 |

## 👀 리뷰 · 머지 규칙

- 🌿 작업은 **새 브랜치를 만들어** 진행하고, 끝나면 `main`에 머지합니다. (별도 `develop` 브랜치는 두지 않습니다.)
- 🔀 머지는 **Squash merge**(여러 커밋을 하나로)를 기본으로 합니다.
- 🔎 리뷰어는 [필수 규칙 5가지](#-필수-규칙-5가지)를 우선 확인합니다.
