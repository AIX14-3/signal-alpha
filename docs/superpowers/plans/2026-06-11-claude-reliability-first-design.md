# 신뢰도 우선 재설계 — Claude 독자 제안

작성일: 2026-06-11 · 작성: Claude (기존 설계 문서와 독립적인 원점 제안) · 목표: **최종 결과값의 신뢰도 극대화**

---

## 0. 핵심 주장 — 문제를 바꿔야 신뢰도가 나온다

"주가가 오를지 내릴지 맞히는 시스템"은 세계 최고 기관도 55%를 넘기 힘들고,
무료 데이터·소규모 표본으로는 **검증조차 어렵다**. 신뢰도 높은 결과를 원한다면 질문을 바꿔야 한다.

> ❌ "이 종목이 오를 확률은?" (절대 방향 예측 — 거의 불가능, 검증 곤란)
> ✅ "지금 시장에서 **어떤 종목이 상대적으로 유리한가?**" (횡단면 상대 순위 — 수십 년 학술·실무 증거 존재, 통계 검증 가능)

점수(0~100)는 "상승 확률"이 아니라 **"전체 유니버스 내 상대 우위 백분위"**로 정의한다.
그리고 신뢰도의 본체는 적중률 숫자가 아니라 **보정(calibration)** 이다:
"80점대 종목들의 과거 실제 20일 수익률 분포는 이랬다"를 그대로 공개하는 것 —
이것이 사용자가 믿을 수 있는 유일한 형태의 데이터다.

---

## 1. 설계 원칙 5개

1. **표본의 크기가 기교를 이긴다** — 30종목 × 3년이 아니라 **KOSPI200 × 10년**.
   횡단면 관측치가 ~20배. 통계 검증력은 모델 개선보다 표본 확대에서 먼저 나온다. (pykrx 무료, 비용 0)
2. **발명하지 말고 재현하라** — 새 룰을 발명해 튜닝하는 순간 과적합이 시작된다.
   수십 년 검증된 팩터(모멘텀·반전·밸류·퀄리티·저변동성·수급)를 구현하고,
   "이 유니버스·이 기간에도 작동하는가"만 검증한다. **가중치 탐색 루프는 하지 않는다** —
   z-score 등가중(또는 학습구간 IC 비례) 고정. 자유 파라미터가 적을수록 신뢰도가 높다.
3. **Point-in-time 규율** — 재무 데이터는 회계기간이 아니라 **공시일** 기준으로 사용
   (3월에 나온 사업보고서를 1월 점수에 쓰면 미래정보 누수). 모든 팩터는 "T일에 실제로 알 수 있었던 것"만으로 계산.
4. **백테스트보다 강한 증거: 포워드 섀도 테스트** — 매일 예측을 결과가 나오기 *전에*
   타임스탬프와 함께 기록(append-only)하고, 미래가 도착하면 대조한다.
   백테스트 편향이 구조적으로 0%인 유일한 검증법. 비용은 시간(4~8주)뿐.
5. **모르면 모른다고 출력한다** — 데이터 결측·변동성 급등 구간에서는 점수에 확신도 등급(A/B/C)을
   붙이고, C등급이면 점수 자체를 보류한다. 신뢰도는 "항상 답하는 것"이 아니라 "틀릴 상황을 아는 것"에서 나온다.

## 2. 시스템 구성 (수집 → 팩터 → 점수 → 검증)

```text
[수집 계층]  pykrx (KOSPI200 일봉·외인/기관 수급, 10년)  ← 무료, 핵심
             DART (재무: 영업이익률·매출증가율·부채비율, 공시일 포함)
             → parquet 저장 (point-in-time 컬럼 포함) + 무결성 테스트 스위트

[팩터 계층]  순수 함수 6종 (LLM 없음, 결정적)
             ① 모멘텀 12-1   ② 단기반전 1M    ③ 밸류 (PBR/PER 역수)
             ④ 퀄리티 (영업이익률 수준·개선)   ⑤ 저변동성   ⑥ 외인·기관 수급 (한국 특화)

[점수 계층]  팩터별 횡단면 z-score → 고정 가중 결합 → 백분위 0~100
             + 보정표 (점수 구간별 실제 미래 수익률 분포)
             + 확신도 등급 (결측률·시장 변동성 기반 A/B/C)

[검증 계층]  L1 데이터 무결성 (수정주가·분할·거래정지 자동 테스트)
             L2 팩터 재현성 (알려진 팩터가 알려진 방향으로 작동하는지 단독 IC)
             L3 워크포워드 OOS + 순열 검정 (셔플 500회, p<0.05)
             L4 포워드 섀도 테스트 (매일 기록 → 4~8주 후 대조)  ← 최종 신뢰도 증거
```

### 왜 LLM이 핵심 경로에 없는가
LLM 판단은 재현 불가능(같은 입력, 다른 출력)하여 검증 체계 전체를 무너뜨린다.
뉴스·공시 텍스트 해석은 Phase 7 이후 "추가 팩터 후보"로만 실험하고,
**기존 팩터 대비 증분 IC가 순열 검정을 통과할 때만** 편입한다.

## 3. 점수의 최종 형태 (사용자에게 보여줄 것)

```json
{
  "ticker": "000660",
  "score": 78,                       // KOSPI200 내 상대 우위 백분위
  "confidence": "A",                 // 데이터 완전성·국면 안정성
  "calibration": {                   // 78점대의 역사적 실제 분포 — 신뢰도의 본체
    "horizon_days": 20,
    "median_excess_return": "+1.4%", // 시장 대비 초과수익 중앙값
    "p25_p75": ["-2.0%", "+5.1%"],
    "sample_size": 3120
  },
  "drivers": ["수급 +", "퀄리티 +", "밸류 중립"],   // 점수의 근거 팩터
  "warning": "...", "disclaimer": "..."             // 법적 고지 (프로젝트 정책 유지)
}
```

"점수 78 = 오를 확률 78%"가 **아니라** "과거 이 점수대 종목들의 실제 분포가 이랬다"를
있는 그대로 제공 — 과장 없이 검증 가능한 형태라서 신뢰도가 생긴다.

## 4. 단계별 로드맵

| Phase | 작업 | 완료 판정 (게이트) |
| --- | --- | --- |
| 1 | **데이터 기반** — pykrx KOSPI200 10년 일봉+수급 적재, DART 재무(공시일 포함), parquet + 무결성 테스트 | L1 테스트 전부 통과, 결측 지도 문서화 |
| 2 | **팩터 6종 구현 + 단독 검증** — 팩터별 워크포워드 단독 IC | 최소 3개 팩터가 양(+) IC & p<0.05 — 실패 시 데이터 버그부터 의심 |
| 3 | **결합 점수 + 보정표 + 확신도** — 고정 가중 결합, 점수구간별 수익률 분포표 | 보정표 단조성 (높은 점수 구간 ≥ 낮은 구간) |
| 4 | **전체 OOS 평가** — 워크포워드(반년 단위) + 순열 검정 + 국면별(상승/하락/횡보) 성능표 | 검증 구간 IC>0.03 & p<0.05, 하락장 포함 일관성 |
| 5 | **포워드 섀도 테스트 가동** — 매일 점수 기록(append-only, 결과 도착 전), 4~8주 운영 | 섀도 기간 IC가 백테스트 신뢰구간 내 |
| 6 | **신뢰도 보고서 + 서비스 연결** — FastAPI 엔드포인트, 보정표·한계 명시 | 사용자 최종 승인 |

**Claude 자율 루프의 역할 (재정의):** 가중치 탐색이 아니라 **신뢰도 사냥** —
데이터 누수·버그·이상 종목·생존 편향 흔적을 자율 반복 탐지하고, 발견 시 수정→전 단계 재검증.
파라미터를 늘리는 루프가 아니라 **오류를 줄이는 루프**가 신뢰도를 만든다.

## 5. 솔직한 한계 (보고서에 반드시 명시)

1. **생존 편향**: pykrx는 현재 상장 종목 기준 — 상장폐지 종목 누락으로 성과가 낙관 편향될 수 있음.
   KOSPI200 대형주 위주 구성으로 완화되지만 0은 아님.
2. **상대 순위 ≠ 절대 수익**: 시장 전체가 하락하면 1등 종목도 하락한다. 점수는 "시장 대비"임을 항상 표기.
3. **과거 ≠ 미래**: 팩터 효과는 시기에 따라 약해진다. 섀도 테스트를 상시 운영해 열화를 감시.
4. 투자 권유 표현 금지 정책 유지 — 모든 출력에 warning + disclaimer 필수.
