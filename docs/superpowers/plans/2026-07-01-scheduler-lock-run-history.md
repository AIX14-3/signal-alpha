# Scheduler Lock And Run History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent duplicate scheduler firing and persist a queryable execution history for scheduler runs.

**Architecture:** Keep `run_scheduler_instance.py` as a trigger orchestrator. Add a scheduler-level PostgreSQL advisory lock around each due/manual run, and add a backend-owned `collection_schedule_runs` table plus repository methods so scheduler runs are recorded without moving collection or analysis logic into `main-server`.

**Tech Stack:** Python 3.11, asyncpg-compatible repositories, FastAPI admin routes, PostgreSQL migrations, pytest, ruff.

---

## File Structure

- Modify `services/agent-worker/run_scheduler_instance.py`: acquire/release scheduler advisory lock and create/update run history rows around `_fire()`.
- Create `services/agent-worker/tests/test_scheduler_instance.py`: unit tests for lock-held behavior and run-history recording.
- Modify `packages/data-access/signal_alpha_data_access/repositories/collection_schedules.py`: add run-history repository methods.
- Add migration `database/migrations/20260701_1200_collection_schedule_runs.sql`: create `collection_schedule_runs`.
- Modify `services/main-server/app/api/routes/admin.py`: expose recent run history under admin schedules.
- Create or modify `services/main-server/tests/test_admin_schedule_runs.py`: verify admin route serializes recent runs.
- Modify `docs/runbooks/agent-pipeline-schedule.md`: document advisory lock and run-history table.

- [ ] **Step 3: Implement minimal lock handling**

Add a constant, helper functions, and wrap the firing path:

```python
_SCHEDULER_ADVISORY_LOCK_KEY = 0x53434844

async def _try_scheduler_lock(connection: Any) -> bool:
    return bool(await connection.fetchval("SELECT pg_try_advisory_lock($1)", _SCHEDULER_ADVISORY_LOCK_KEY))

async def _release_scheduler_lock(connection: Any) -> None:
    await connection.fetchval("SELECT pg_advisory_unlock($1)", _SCHEDULER_ADVISORY_LOCK_KEY)
```

In `run_cycle()`, after the schedule is due but before `_fire()`, return `lock-held` if the lock cannot be acquired. Release the lock in `finally`.

    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
