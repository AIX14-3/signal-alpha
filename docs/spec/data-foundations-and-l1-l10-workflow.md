# Part 1. 꼭 추가해야 할 토대 (지금 설계에 반영)

> 공통 기준: **"늦게 고치면 과거 데이터·백테스트를 통째로 다시 만들어야 하는가?"** → 그렇다면 지금.

## A. 시점 정합성(PIT) · 정정 처리 ⭐ 최우선

**문제**: 지금은 look-ahead 방지 원칙이 L6 한 줄뿐. 멱등 upsert가 과거 값을 덮어써서, **미래에 알게 된 값이 과거 신호에 새어들** 수 있다(백테스트 과대평가 → 실전 붕괴).

**원칙**
1. 모든 레코드에 **두 시점**을 둔다:
   - `event_ts` — 사건 발생 시점(거래일 등)
   - `known_at` — **그 정보를 외부에서 알 수 있게 된 시점**(공시 접수일 `rcept_dt`, 재무 보고서 제출일, 가격 거래일)
2. **신호·백테스트는 `known_at ≤ 평가시점`인 데이터만** 사용한다(PIT 조회).
3. **정정(restatement)은 덮어쓰지 않는다 — 새 버전으로 보존(append-only).**
   - 정정 공시는 **새 `rcept_no` + 새 `known_at`** 으로 행을 추가.
   - 조회는 "그 시점 기준 최신 유효본"을 고른다.
   - → L1 등의 멱등 upsert 자연키에 **버전 축(rcept/effective)** 을 포함하거나 별도 이력 테이블을 둔다.

**적용 지점**: L1~L5 모든 적재 스키마에 `known_at`(필수) + 정정 버전 컬럼. 백테스트(L6)·feature store(B)는 PIT 조회만 허용.

## B. feature store 스펙 ⭐

**문제**: 여러 소스 신호를 묶는 "feature store"를 전제하면서 정의가 없다. 이게 L6의 입력이다.

**정의**: 모든 소스 신호를 **(ticker, ts) 시계열**로 정렬·조인하고 **PIT를 보존**하는 조회 계층. (`signal_events` 위의 as-of join 뷰/서비스)

**스펙**
- **as-of join**: `get_features(ticker, asof)` = `known_at ≤ asof`인 각 feature의 최신값만 반환.
- **결측 정책**: forward-fill 허용 범위(예: 재무는 다음 보고 전까지 유효), 만료(stale) 기준 명시.
- **표준 인터페이스**: 소스가 늘어도 동일 계약으로 조회(컬럼=source/metric).
- **재현성**: 같은 `asof`로 조회하면 항상 같은 결과(PIT 보존).

**적용 지점**: L6·L7~L10·분석기 전부 feature store를 통해서만 과거 값을 읽는다(직접 테이블 PIT 우회 금지).

## C. 백테스트 평가지표 표준

**문제**: 채택 기준이 "lift"로만 추상적. 게이트가 측정 가능해야 한다.

**채택 메트릭(정의)**
- **IC(정보계수)**: 신호 강도 ↔ forward return 상관(랭크 IC 권장).
- **hit rate**: 방향 적중률.
- **forward abnormal return**: 1/5/20d, **시장·섹터 벤치 대비**.
- **decay**: 신호 효력의 시간 감쇠(언제까지 유효).
- **turnover / 거래비용**: 신호 갱신 빈도·체결비용 반영.
- **통계 유의성**: 표본 수·p값/부트스트랩.

**평가 환경**
- **유니버스 스냅샷**: 각 시점의 실제 구성(상폐·신규상장 포함) → **생존편향 차단**.
- **벤치마크**: 시장(KOSPI/S&P) 및 섹터.
- **look-ahead 차단**: A의 PIT 원칙 준수(이벤트 시점 이후 가격만).
- **채택 임계치**: 메트릭별 합격선을 사전 고정(사후 조정 금지).

## D. 데이터 품질 · 소스 드리프트 감지(DQ)

**문제**: DART/SEC 등 외부 소스는 **말없이** 응답 포맷·필드를 바꾸거나 빈다.

**원칙**
- **스키마 계약 테스트**: 응답 필수 필드/타입 검증(깨지면 적재 차단·알림).
- **적재량·결측·이상치 모니터**: 일별 적재 건수·널 비율·범위 이탈 추적, 급변 시 알림.
- **소스 버전 추적**: 엔드포인트/필드 변경 감지.
- **격리**: DQ 실패 데이터는 정상 테이블에 섞지 않고 격리·재처리.

# Part 3. L1~L10 워크플로우

## 공통 파이프라인 (모든 레이어가 따른다)
```
[수집] → [정규화] → [적재] → [feature store] → [신호 emit] → [백테스트] → [채택]
 소스    단위·통화·    멱등/버전    PIT as-of      공통 스키마    평가지표      게이트
 API     시차 + PIT   (known_at)   조인(B)        (협업안 §8)    (C)          (lift)
         (A)
```
- 모든 적재는 **A(PIT/정정)**, 모든 조회는 **B(feature store)**, 모든 채택은 **C(평가지표)** 를 거친다.
- L1~L6 = 토대(즉시 가치). L7~L10 = 상위 활용(토대 입증 후, 구현 수단은 범위 밖).

## 레이어별 워크플로우

| 레이어 | 수집(소스) | 적재(테이블) | 산출/신호 | 의존 |
|---|---|---|---|---|
| **L1 정형 재무** | OpenDART `fnlttSinglAcntAll` | `dart_financial_facts`(+known_at) | ★4 YoY/QoQ·부채비율·CAPEX 신호 | — |
| **L2 지분·내부자** | `majorstock`·`elestock` | `dart_ownership_events` | 내부자 순매수/매도 추세 신호 | L5(엔티티) |
| **L3 임직원** | `empSttus` | `dart_employee_stats` | 고용 모멘텀(★크로스 NPS/채용) | L1 |
| **L4 비정형 corpus** | DART/SEC 본문 섹션 | 신규 `document_sections`/`document_chunks` 계열 | RAG 검색·톤 신호의 evidence | — |
| **L5 엔티티·관계** | corp_code·CIK·발주처 추출 | `entities`/`entity_relations` | 공급망 동반 feature | L4 |
| **L6 백테스트 패널** | `signal_events`⨯`ohlcv_data` | `event_study_panel` | **채택의 심판**(신호 소비) | A·B·C, 모든 신호 |
| **L7 멀티스텝 추론·시나리오** | (L1·L4·L5 종합) | (신호 후보) | 멀티섹션 근거 종합 → 구조화 thesis 후보 | L1~L5, L6 게이트 |
| **L8 예측·ML** | feature store | ML 모델·예측 | 부실 조기경보·어닝 예측 신호 | B, 라벨(L6) |
| **L9 인과추론** | L6 패널 확장 | 인과 검증 결과 | 이벤트 인과 lift 정교화 | L6 |
| **L10 자율 thesis·멀티모달** | 전 소스 종합 | 구조화 thesis | Bear/Base/Bull(가드레일·사람 경계) | L7·L8·L9 |

> L7~L10은 **L1~L4 적재 + L6 백테스트 lift 입증** 후 착수. 구현 수단(오케스트레이션/모델링 도구)은 본 문서 범위 밖에서 별도 결정한다.

## 의존 순서 (착수 권장)
```
L1 재무 ─┐
L2 지분  ├─► (신호 적재) ─► L6 백테스트 ─(lift 입증)─► L7·L8·L9·L10
L3 임직원 │
L4 corpus ├─► L5 엔티티·관계
```
1. **토대 먼저**: A·B·C·D 원칙 합의 → L1·L2·L3 적재(동일 패턴) → L4 corpus.
2. **신호+심판**: 공통 스키마 emit → L6 백테스트로 lift 검증.
3. **상위 활용**: 입증된 신호 위에서만 L7~L10.
