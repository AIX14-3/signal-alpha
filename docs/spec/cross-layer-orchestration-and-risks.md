# L1~L10 교차연결 오케스트레이션 & 리스크 비중 판단

> 두 가지를 담는다. **Part A** = L1~L10이 갖춰졌을 때 레이어 간 상호관련을 판단해 "분석할지·재수집할지·검증할지"를 LangGraph 루프로 제어하는 **컨트롤 플레인** 구상(미구현·비전). **Part B** = 개발 시 어떤 우려에 얼마의 비중을 둘지 결정하게 돕는 **리스크 레지스터**.
> 연결: `data-layers-l2-l10-spec.md` · `data-program-roadmap.md` · `협업안_검색트렌드_에이전트.md`.

# Part A — 교차연결 컨트롤 플레인 (LangGraph)

## A-0. 아이디어
L1~L10은 각자 신호를 내는 "레이어"지만, 실제로는 **서로 연관**된다. 한 레이어에 새 데이터가 들어오면 관련 레이어를 깨워 **추가 수집 / 검색(RAG) / 데이터 정확성 검증 / LLM 분석**을 할지 판단하고, 필요하면 루프를 돈다. 이 **판단·라우팅·루프 제어**를 LangChain/**LangGraph**가 맡는다(= control plane).

> **예시(사용자 시나리오)**: L1(정형 재무)에 신규 데이터 유입 → 라우터가 "L3(임직원)·L7(시나리오 추론)·L10(종합 thesis)와 연관" 판정 → 그 3개의 **연결점 데이터를 다시 가져와** 재분석.

## A-1. 레이어 연관 맵 (트리거 그래프)
어느 레이어 이벤트가 어느 레이어를 깨우는지의 **기본(결정형) 규칙**. LLM이 아니라 설정으로 관리(나중에 학습/가중).

| 트리거(유입) | 연관 레이어 | 연관 사유(예) |
|---|---|---|
| **L1 재무** | L3, L6, L7, L8, L10 | 재무 변화 → 고용효율(L3)·백테스트(L6)·시나리오(L7)·예측feature(L8)·thesis(L10) |
| L2 지분 | L5, L7, L10 | 지분이동 → 엔티티/지배구조(L5)·시나리오(L7) |
| L3 임직원 | L1, L7 | 고용 모멘텀 ↔ 재무·시나리오 |
| L4 corpus | L5, L7, L10 | 본문 → 발주처 추출(L5)·멀티섹션 RAG(L7) |
| L5 엔티티/관계 | L7, L10 | 공급망 edge → 동반 시나리오 |
| L6 백테스트 | (게이트) | 채택/기각 피드백을 라우팅 가중에 반영 |
| L7~L10 | L4, L1~L5 | 추론 중 근거 부족 → 하위 레이어 재조회(루프) |

## A-2. LangGraph 루프 (노드)
```
        ┌────────────────┐
 이벤트→│ relation_router │  연관 맵(A-1) 조회 → 깨울 레이어 집합 결정 (대부분 결정형)
        └───────┬────────┘
                ▼
        ┌────────────────┐
        │ relevance_judge │  애매할 때만 LLM: "이 변화가 정말 L7과 관련?" (비용 절감)
        └───────┬────────┘
         관련 X │ 관련 O
           END  ▼
        ┌────────────────┐
        │  fetch / retrieve │  연결점 데이터 재수집(API) 또는 L4 전용 corpus 검색
        └───────┬────────┘
                ▼
        ┌────────────────┐
        │  verify (DQ)    │  데이터 정확성 검증: 결측·이상치·PIT·정정 충돌
        └───────┬────────┘
       불충분 ↺  │ 충분               (루프: 근거 부족 시 fetch로 복귀, 상한 내)
                ▼
        ┌────────────────┐
        │  analyze (LLM)  │  연관 레이어 종합 해석 → 구조화 출력 + 인용 + 가드레일
        └───────┬────────┘
                ▼
        공통 신호 스키마 emit (evidence_ref 포함) → 백테스트(L6)
```

> ⚠️ 위는 **논리 흐름**일 뿐, 그래프 프레임워크가 필요하다는 뜻이 아니다.
> 어떤 파이프라인도 박스-화살표로 그리면 그래프처럼 보인다. 구현 수단은 §A-4에서 별도 판단한다.

## A-3. 설계 원칙 (비용·안전 통제)
- **라우팅은 결정형 우선**: A-1 연관 맵 = 코드/설정. LLM은 "애매한 관련성 판정"·"종합"에만(협업안 §4와 동일 철학).
- **루프 상한**: 최대 반복 수·최대 재수집 호출·토큰/비용 상한을 노드 상태에 둔다(폭주 방지).
- **데이터 정확성 검증(verify)을 1급 노드로**: 재수집한 값이 PIT·정정과 충돌하면 분석 전에 차단.
- **근거 추적 필수**: 모든 재수집/판정은 `evidence_ref`로 출처 기록. 없으면 emit 금지.
- **출력은 공통 스키마**: 컨트롤 플레인 결과도 `Signal{...}`로 emit → **백테스트가 "교차분석이 단일신호보다 lift를 더하는가"를 심판**.
- **사람 경계 유지**: 최종 thesis는 가드레일·백테스트 틀 안에서. 자율 매수/매도 결론 금지.

## A-4. 구현 수단 결정 — 프레임워크 없이 먼저

이 컨트롤 플레인은 **기본적으로 LangChain/LangGraph가 필요 없다.** 분해하면:

| 구성요소 | 실제 정체 | 수단 |
|---|---|---|
| relation_router (A-1) | 연관 맵 dict 조회 + 다운스트림 태스크 트리거 | **기존 queue 오케스트레이터**(`orchestrator/queue/handlers.py`) |
| fetch / retrieve / verify | API 호출·DB 조회·RAG·DQ 체크 | **평범한 함수/리포지토리** |
| analyze | 단일 구조화 출력 | **`gemini_client` + function calling** |
| **loop**(근거부족→재fetch) | LLM이 충분성 판단하며 도는 동적 루프 | **경계 있는 self-built `while` 루프** |

→ **1차 구현 = queue + 함수 + function calling + 경계 루프.** 프레임워크 0.

**LangGraph는 아래가 "모두" 충족될 때만** 그 동적 루프에 한해 조건부 도입:
- [ ] 한 판단에 **여러 LLM 사이클**(재조회→재판단)이 일상적
- [ ] 분기·병렬 fan-out 후 **상태 병합** 필요
- [ ] self-built 루프의 상태·재시도·중단·재개 관리가 **유지보수 부담**이 됨
- [ ] L1~L4 적재 + **L6 백테스트로 "교차분석이 lift를 더한다"가 입증**됨

> **LangChain 본체(체인/에이전트 추상화)는 이 구조에 이점이 없어 비추천.** 후보는 LangGraph(상태 루프)뿐이다.
> 지금 할 일: **A-1 연관 맵을 설정으로 먼저 정의** → 코드 없이도 L2~L6 설계가 정합. 구현은 L7+ 게이트 후.

## A-5. 랭체인/랭그래프를 "언제·어떻게" 설계해야 합당한가 (일반 가이드)

**3단 사다리 — 항상 아래에서 위로, 위 칸의 조건이 차야 올라간다.**

| 단계 | 도구 | 합당한 경우 | 신호 α 예 |
|---|---|---|---|
| 1 | **함수 호출(function calling)** | 단발 분류·추출·요약, 결정형 라우팅, 도구 1~2개 | ★5 단문서 추출, analyze 노드 |
| 2 | **self-built 루프** | 다단계지만 흐름이 고정/반결정형, 경계 있는 반복 | A-2 컨트롤 플레인 1차 구현 |
| 3 | **LangGraph** | 흐름이 **LLM 주도로 동적**, 다중 사이클·분기·상태 병합·중단/재개, 손으로 짠 루프가 유지보수 고통 | L7 thesis 에이전트, 트렌드 attention 에이전트 |

**LangGraph 설계가 합당하다면, 이렇게 설계한다(원칙):**
1. **노드 대부분은 결정형 도구**, LLM 노드는 "애매한 판정·종합"에만 (비용·환각 최소화).
2. **상태에 예산을 박는다** — 최대 사이클/호출/토큰, 방문 집합(순환 차단), 중단 조건.
3. **모든 LLM 출력은 구조화 + `evidence_ref` + 가드레일** 통과. 근거 없으면 emit 금지.
4. **출력은 공통 신호 스키마** → 백테스트가 "에이전트가 단일 신호보다 lift를 더하나" 심판.
5. **사람 경계 유지** — 최종 매수/매도 thesis는 자율 생성 금지(`협업안` §5).
6. **체크포인트/재개**가 정말 필요할 때만 LangGraph persistence 사용(아니면 과함).

**합당하지 않은(=함정) 신호:**
- "다이어그램이 그래프처럼 생겼다" → 모든 파이프라인이 그렇다. 근거 아님.
- "나중에 복잡해질 것 같다" → YAGNI. 복잡해지면 그때 그 루프만 이관.
- 단발 prompt→response·선형 파이프라인·결정형 라우팅 → **1단(함수 호출)이 정답.**

> 한 줄: **"이 흐름의 다음 단계를 LLM이 동적으로 정하는가, 그리고 그걸 손으로 짜면 아픈가?"** 둘 다 예일 때만 LangGraph. 그 전엔 함수 호출/self-built 루프. LangChain 본체는 거의 항상 불필요.

# Part B — 우려 상황 레지스터 & 비중 판단

## B-0. 비중 판단 프레임
각 우려를 아래로 점수화해 **개발 시 투자 비중**을 정한다.

```
비중 점수 = 심각도(1~3) × 발생가능성(1~3)        (1=낮음, 3=높음)
처리 시점 = 지금(토대) | 중기(신호 적재기) | L7+(추론 도입기)
```
- **High(6~9)**: 지금 설계에 반영(나중에 고치면 데이터/백테스트를 다시 만들어야 함).
- **Med(3~4)**: 신호가 쌓이기 시작할 때.
- **Low(1~2)**: 해당 기능 도입 시.

> 핵심 기준: **"늦게 고치면 과거 데이터·백테스트를 통째로 다시 만들어야 하는가?"** → 그렇다면 무조건 지금(High).

## B-1. 리스크 레지스터

| # | 우려 상황 | 증상/결과 | 심각×가능=점수 | 처리 시점 | 완화책 |
|---|---|---|---|---|---|
| R1 | **PIT 깨짐(look-ahead)** | 미래 정보가 과거 신호에 샘 → 백테스트 과대평가, 실전 붕괴 | 3×3=9 **High** | **지금** | 모든 값에 as-of 시점, "그 시점 가용값"만 사용 |
| R2 | **정정공시(restatement)** | 멱등 upsert가 과거 재무를 덮어씀 → 과거 신호 오염 | 3×3=9 **High** | **지금** | 정정을 신규 시점 이벤트로 보존(버전), 원본 불변 |
| R3 | **feature store 부재** | 소스별 시점·조인 제각각 → 교차/백테스트 불가 | 3×2=6 **High** | **지금~중기** | ts 정렬·PIT 보존 공통 계층 스펙화 |
| R4 | **평가지표 미정의** | "lift" 추상 → 채택 기준 자의적 | 2×3=6 **High** | **지금** | IC·hit rate·abnormal return·decay·turnover + 유니버스/벤치/생존편향 표준 |
| R5 | **소스 드리프트** | DART/SEC 응답 포맷·폼 변경에 말없이 깨짐 | 3×2=6 **High** | 중기 | 스키마 계약 테스트 + 적재량/결측 모니터 |
| R6 | **재수집 루프 폭주(컨트롤 플레인)** | LangGraph 루프가 무한 재수집 → 비용·rate 폭발 | 3×2=6 **High** | L7+ (설계는 지금) | 루프/호출/토큰 상한, 결정형 라우팅 우선 |
| R7 | **LLM 라우팅 오판** | 관련 없는 레이어를 깨워 비용·노이즈 | 2×2=4 **Med** | L7+ | 관련성 판정은 임계치+결정형, LLM은 애매할 때만 |
| R8 | **데이터 정확성 미검증** | 재수집 값 오류가 분석/신호로 전파 | 3×2=6 **High** | 중기 | verify 노드(DQ) 1급화, 분석 전 차단 |
| R9 | **순환 트리거** | L1→L3→L1… 연관 맵 사이클 | 2×2=4 **Med** | L7+ | 방문 집합·깊이 제한, DAG화 |
| R10 | **비용·rate·키 관리** | OpenDART/SEC/LLM 쿼터 초과·키 노출 | 2×3=6 **High** | 중기 | 캐싱·백오프·키 로테이션·쿼터 상한 |
| R11 | **컴플라이언스·라이선스** | 약관 위반(데이터랩/구글 비공식/키움 재배포), 자문업 경계 | 3×1=3 **Med** | 중기 | 소스별 약관 표, "추천 아님" 가드레일 유지 |
| R12 | **통화·시차·언어 혼선** | KRW/USD, KST/ET, 국문/영문 섞임 | 2×2=4 **Med** | 중기 | 정규화 계층(currency/tz 필드 필수) |
| R13 | **스키마 거버넌스** | source/event_type/표준계정 사전 난립 | 2×2=4 **Med** | 중기 | enum 사전 + schema_version |
| R14 | **의존성 미선언 반복** | `langchain_text_splitters` 같은 미선언 import로 클린환경 깨짐 | 2×2=4 **Med** | **지금** | 선언 강제, L4 착수 전 정리 |

## B-2. 권장 비중 다이얼 (요약)
- **지금(토대 설계에 반드시 반영)**: R1 PIT · R2 정정 · R4 평가지표 · R3 feature store · R14 의존성. → *늦게 고치면 데이터·백테스트 재작성.*
- **중기(신호 적재 시작 시)**: R5 드리프트 · R8 DQ검증 · R10 비용/키 · R11 컴플라이언스 · R12 정규화 · R13 거버넌스.
- **L7+ 도입 시(설계 방향만 지금 고정)**: R6 루프폭주 · R7 LLM오판 · R9 순환 — Part A 컨트롤 플레인과 함께.

## B-3. 개발자용 한 줄 결정 규칙
> 새 기능을 짤 때: **"이걸 대충 하면 나중에 과거 데이터/백테스트를 다시 만들어야 하나?"** → 예면 지금(High), 아니면 해당 단계로 미룬다. PIT·정정·평가지표·feature store는 거의 항상 "예".
