# Signal Alpha DB Design Summary

## Report RAG Roles

Report RAG is part of the MVP scope. `report_chunks`, `pgvector`, and the embedding index are required for the MVP report analysis flow.

### Report Collector

- Stores report metadata and parsing status in `report_raw_details`.
- Downloads the report PDF or stores its local file path.
- Extracts text from the PDF.
- Stores parsed report chunks in `report_chunks.chunk_text`.
- Does not call an LLM.

### Embedding Worker

- Reads rows from `report_chunks` where `embedding IS NULL`.
- Generates vectors with the selected embedding model, such as BGE-M3.
- Updates `report_chunks.embedding`.
- Must keep the embedding model output dimension aligned with `report_chunks.embedding VECTOR(1024)`.

### Report Analyst

- Performs pgvector similarity search on `report_chunks`.
- Uses related chunks as evidence for LLM analysis.
- Stores normalized and analysis outputs in `signal_events`, `signal_metrics`, `analysis_results`, and `agent_results`.

## Report RAG Search Example

```sql
SELECT
    id,
    raw_document_id,
    stock_id,
    chunk_index,
    chunk_text,
    embedding <=> :query_embedding AS distance
FROM report_chunks
WHERE stock_id = :stock_id
ORDER BY embedding <=> :query_embedding
LIMIT 5;
```

Notes:

- `:query_embedding` is an embedding vector generated by the application.
- Lower `distance` means higher similarity.
- Filter by `stock_id` first so chunks from other stocks are not mixed into the report analysis context.

## Array Column Limits

The following columns are PostgreSQL arrays, so PostgreSQL cannot enforce foreign key integrity for each element:

- `processing_queue.source_raw_ids`
- `processing_queue.source_signal_event_ids`
- `processing_queue.source_analysis_result_ids`
- `analysis_results.source_signal_event_ids`
- `agent_results.source_signal_event_ids`

For the MVP, arrays are kept for fast implementation. After the data model stabilizes, split them into mapping tables such as `analysis_signal_events` and `agent_signal_events`.

## MVP Service Scope

Initial service code should focus on this required flow:

```text
stocks
-> raw_documents
-> report_raw_details
-> report_chunks
-> source_documents
-> signal_events
-> signal_metrics
-> analysis_results
-> agent_results
-> final_signals
```

The following tables are expansion-stage tables:

- `quant_scores`
- `ta_scores`
- `ai_scores`
- `xgb_model_versions`
- `ml_scores`
- `score_history`
- `backtest_results`
- `user_sessions`
- `social_accounts`
- `portone_verifications`
- `terms_agreements`
- `admin_accounts`
- `admin_sessions`
