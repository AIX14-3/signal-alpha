# /experiment — 실험 리포트 생성 + 보관

ML 테스트·백필 검수·모델 경연 등 **실험을 한 건 끝낼 때마다** 호출한다.
방금 돌린 실험의 환경·방법·데이터·결과·해석을 일관된 형식으로 정리해 리포트로 남긴다.

**기본은 개인 보관(git 비추적)이다.** 실험 리포트는 산출물 기록이라 저장소에 올리지
않고 개인 아카이브에 모은다(사용자 방침). 공유가 필요한 리포트만 git에 올린다(아래 §보관 위치).

## 언제 부르나
- ML 하니스/모델 경연/백테스트를 한 사이클 돌리고 결과가 나왔을 때
- 데이터 수집·백필 가능성 검수(dry-run probe)를 마쳤을 때
- 어떤 가설을 데이터로 검증해 결론(또는 무신호)이 나왔을 때

`/devlog`(날짜 단위 작업 연속성)와 역할이 다르다. `/experiment`는 **한 실험 = 한 리포트**.

## 날짜
환경 컨텍스트의 현재 날짜(`currentDate`)를 `YYYY-MM-DD`로 쓴다.

## 보관 위치 (둘 중 택1 — 기본은 개인 보관)
- **개인 보관(기본)**: `C:\Users\804\Documents\signal-alpha-archive\experiments\<날짜>-<슬러그>.md`
  - 저장소 밖이라 git에 절대 안 잡힌다. 폴더 없으면 만든다.
- **git 공유(opt-in)**: 사용자가 "이건 공유/팀 참조용"이라고 명시할 때만
  `docs/experiments/<날짜>-<슬러그>.md`에 둔다.
  - 이 경우 인계(`.claude/devlog/_handoff.md`)·devlog에서 링크로 참조될 수 있음을 알린다.

슬러그는 실험을 한눈에 식별할 짧은 영문 kebab-case(예: `datalab-ml-bakeoff`, `hiring-backfill-feasibility`).

## 리포트 형식 (기존 리포트에서 추출한 템플릿)
아래 골격을 채운다. **실제로 돌린 것만** 적는다(추측·창작 금지). 해당 없는 절은 빼도 된다.

```markdown
# <실험 제목> (YYYY-MM-DD)

> <2~3줄 배경: 무엇을 왜 검증했나 + 방식(실적재/ dry-run/ 로컬 등)>
>
> **한 줄 결론: <신호 유/무, 핵심 수치 하나, 한계까지 한 문장으로>**

---

## 1. 실행 환경
| 항목 | 값 |
|---|---|
| 실행기 | <로컬/원격, OS, GPU 유무> |
| Python / 라이브러리 | <버전 — 재현에 필요한 것> |
| DB / 데이터 출처 | <Supabase prod / CSV / API 등> |

## 2. 실행 메타
- 브랜치 / 코드 위치: <어디 코드로 돌렸나, 커밋 여부>
- 타깃(예측 대상) / 라벨 정의: <초과수익률·방향 등>
- 공통 파라미터: <lookback·seed·fold·neutral_band 등>
- 스윕 축: <horizon·종목·모델 등>

## 3. 데이터 — 유니버스 · 자료 · 근거
- 유니버스(종목/카테고리)와 그 한계(표본 수·동조성 등)
- 수집 자료 표: | 자료 | 출처/API | 저장 | 행수 | 기간 |
- 왜 이 자료인가(근거) / 무결성 검증(백필 inserted·skip·fail, sanity 체크)
- 누수 차단: 피처는 신호일 이전만, 라벨은 이후만, 워크포워드 날짜경계 분할

## 4. 방법론
- 모델/기법, 평가 프로토콜(워크포워드 fold 등), 지표(IC·rankIC·accuracy·Dbase 등)
- 판정 규칙(무엇을 "신호 있음"으로 보나)

## 5. 결과
- 핵심 표(horizon/종목별 표본·중앙값 rankIC·양수 비율·sd 등)
- 2021만 vs 전체 같은 **재검증 비교**가 있으면 함께(신기루 검출 여부)

## 6. 해석 · 판정
- 확정 결론 + 그 근거. 소표본 우연/다중비교 주의. 가설 기각/채택 명시.

## 7. 이상치 · 주의 / 한계
- 다중비교, 표본 규모 게이트 미달, 결과 파일 비추적 등.

## 8. 산출물
- 코드/스크립트 경로, 결과 CSV(로컬 비추적), 재현 명령 한 줄.

## 9. 다음 단계
- 후속 레버(종목확대·다중소스융합·평가전환 등) 체크리스트.

---
관련 메모리: <[[ml-bakeoff-datalab-result]] 등 연결>
```

## 절차
1. **사실 수집**: 이번 실험의 실제 명령·파라미터·출력(지표 표)·데이터 행수를
   대화/로그/`git diff`/결과 CSV에서 모은다. **숫자는 실제 산출물에서만** 가져온다.
   모르거나 안 돌린 값은 비우지 말고 `TODO`/`미측정`으로 표시한다.
2. **보관 위치 확정**: 사용자가 "공유용/git"이라 하지 않았으면 **개인 보관(기본)**.
   폴더가 없으면 만든다.
3. **리포트 작성**: 위 템플릿을 채워 `<날짜>-<슬러그>.md`로 저장한다.
4. **Notion 자동 업로드**: 리포트 저장 직후 push 스크립트를 실행해 Notion DB에 한 페이지로 올린다.
   ```bash
   uv run python services/agent-worker/scripts/push_to_notion.py "<저장한 리포트 경로>" --tags "<소스>,<결과>"
   ```
   - 환경변수 `NOTION_API_KEY`·`NOTION_PARENT_ID`(DB ID)가 필요하다. **없으면 이 단계만
     조용히 건너뛰고**(에러로 작업을 막지 않음) 로컬 저장은 그대로 둔다.
   - 스크립트는 마크다운(표 포함)을 Notion 블록으로 변환하고, DB 속성을 **타입**으로 자동
     매핑한다(title=제목, date=날짜, rich_text(결론/conclusion/summary)=한 줄 결론,
     multi_select(태그/소스)=`--tags`).
   - `--tags`는 실험을 분류할 짧은 키워드(예: `DATALAB,무신호` / `HIRING,backfill가능`).
5. **메모리 연결**: 관련 자동메모리(예: ML 모델경연 결과)가 있으면 `[[슬러그]]`로 링크하고,
   결과가 프로젝트 방향을 바꾸는 사실이면 해당 메모리 파일도 갱신할지 사용자에게 제안한다.
6. **완료 보고**: 저장 경로 1줄 + (개인 보관이면) "git 비추적"임을 명시 + Notion 업로드
   결과(페이지 URL 또는 "토큰 없어 스킵"). git 공유로 넣었으면 인계 참조 가능성을 알린다.

## 주의
- **창작 금지**: 돌리지 않은 모델·없는 수치를 만들지 않는다. 실제 결과 표가 핵심이다.
- **결과 파일(CSV/JSON)은 커밋 금지** — 리포트(요약)만 남기고 원시 산출물은 로컬 보관.
- 스코프는 대체데이터(HIRING·PATENT·DATALAB·aggregator). 주가팀 테이블(`ohlcv_data` 등)
  직접 변경 금지 — 주가는 CSV 경로로만 흐른다.
